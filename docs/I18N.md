# Internacionalización permanente

Rave soporta español (`es`), polaco (`pl`) e inglés (`en`) con igual condición. Una feature de interfaz no está terminada si falta alguno. Esta regla está en [AGENTS.md](../AGENTS.md) y se verifica en CI en cada push y PR.

## Arquitectura y claves

`apps/web/src/i18n/es.ts` define las claves semánticas y los parámetros de interpolación. `types.ts` deriva `Key`, `Catalog` y `Translator`. `pl.ts` y `en.ts` usan `satisfies Catalog`: omitir o añadir claves inesperadas falla en TypeScript. El test compara estructura, valores no vacíos y parámetros, incluidas todas las formas plurales. No hay una biblioteca i18n adicional.

En un componente:

```tsx
const { t, number, date } = useI18n();
<button>{t("player.fullscreen")}</button>;
<p>{t("watch.startPersonal", { time: time(position) })}</p>;
```

Para añadir texto, crea una clave descriptiva en ES, PL y EN en el mismo cambio. Conserva los nombres de parámetros en los tres catálogos; cada traducción decide su posición. TypeScript rechaza claves desconocidas, parámetros ausentes o incorrectos. No concatenes fragmentos de frases.

Las cantidades usan mensajes con `one`, `few`, `many`, `other` y el parámetro numérico `count`, por ejemplo `t("account.sessionCount", { count: sessions.length })`. `Intl.PluralRules` decide la forma: en polaco 1, 2/22, 5/12/101 y fracciones no siguen la regla española singular/plural. Las cuatro formas se mantienen en todos los catálogos, aunque algunas coincidan o no se utilicen en un locale.

`number` y `date` usan `Intl` con `es-ES`, `pl-PL`, `en-GB`. Las duraciones de reproducción `01:23:45`, unidades técnicas (GiB, s), IDs, URLs y etiquetas reales de pistas no cambian datos almacenados.

## Selección y persistencia

`packages/contracts/src/locale.ts` define los locales y defaults. `preferencesSchema` valida `locale`. La API existente `PATCH /api/v1/account` acepta `{ preferences: { locale: "pl" } }` y fusiona JSON sin borrar otras preferencias. No se necesita migración. Las cuentas existentes sin locale reciben OWNER → `es`, PARTNER → `pl`, usando el rol estable, aunque se cambie su nombre.

Antes del login: elección explícita en `localStorage["rave-locale"]`, después `navigator.languages` compatibles, finalmente ES. Solo se almacena el código de idioma, sin datos sensibles. Tras login, `/auth/me` o activación, el locale guardado de la cuenta/default por rol es autoritativo. El selector está en login, activación, Cuenta y navegación; este último permite cambiar presentación durante la reproducción. El cambio es inmediato, se guarda en servidor y revierte con un error localizado si falla. Durante la petición ambos selectores autenticados se deshabilitan. Una nueva carga o dispositivo recupera la preferencia; no hay sincronización push entre dispositivos.

`I18nProvider` mantiene React actualizado y `html.lang`. Los efectos que cargan el motor y conectan Socket.IO no dependen de locale ni traductor. Los avisos duraderos guardan claves/códigos, no texto ya traducido. El chat, los nombres, títulos, capítulos y subtítulos introducidos por usuarios se conservan literalmente. El idioma de una pista de subtítulos es independiente del idioma de interfaz.

## Errores y fallback

La API mantiene códigos estables. `ApiError` guarda el código y `Notice` llama a `errorText` en cada render. Los errores HTTP, socket y cliente conocidos se traducen; errores arbitrarios de navegador/proveedor reciben el mensaje genérico localizado sin revelar URLs privadas. Los diagnósticos usan nombres técnicos estables con etiquetas localizadas. Las etiquetas antiguas de sesión `Recuperación`/`Navegador` se reconocen sin modificar filas; las nuevas recuperaciones usan `PASSWORD_RESET`.

`createTranslator` usa ES como fallback runtime ante un valor ausente/vacío y avisa en desarrollo. Esto evita romper la aplicación, pero `catalogIssues` y `satisfies Catalog` impiden publicar un catálogo incompleto. Nunca borres una traducción para hacer pasar un test.

## Control de texto hardcodeado

`scripts/eslint-i18n.mjs` analiza AST en todo `apps/web/src` salvo los tres catálogos. Detecta JSX humano, aria/alt/title/placeholder/label, mensajes literales y plantillas/concatenaciones humanas. Los tests positivos y negativos protegen la regla. No se excluyen páginas ni componentes.

Se permiten imports, tipos literales, claves/IDs/códigos, URLs/MIME, atributos HTML técnicos, selectores CSS, clases/estilos y símbolos/números. La lista mínima de nombres incluye Rave privado, Google Drive, HLS/DASH/SRT/VTT/PiP y los autonyms Español/Polski/English. Dos mensajes internos de proveedor React son errores de programación. Las etiquetas antiguas de dispositivo solo se permiten en comparaciones. Logs de desarrollo son técnicos. Documentar y probar cualquier excepción nueva.

Un análisis estático no puede decidir si datos externos o una variable calculada son texto de producto. La revisión debe comprobar esas fronteras: códigos/estados estructurados pasan por `label`/`errorText`; contenido del usuario se muestra sin traducir. Nunca usar las excepciones técnicas para esconder copy de una feature.

## Pruebas y CI

```sh
pnpm test:i18n
pnpm lint
pnpm typecheck
pnpm test:unit
RAVE_CONFIG_FILE=.local/validation/config.json pnpm test:integration
pnpm exec playwright test tests/e2e/i18n.spec.ts
```

Preparar namespaces y medios sintéticos mediante `pnpm test:prepare` y `tsx scripts/test-prepare.ts validation`; ver la guía de operación para requisitos locales. Nunca apuntar tests a producción.

`tests/unit/i18n.test.ts` verifica I18N-01/02/03/04/05/08/15/16/19, interpolación y plurales. `tests/integration/i18n.test.ts` prueba preferencias reales, defaults, aislamiento, sesiones y rechazo de locale/CSRF inválidos. `tests/e2e/i18n.spec.ts` cubre selector prelogin, autoridad de cuenta, persistencia/reload/nuevo dispositivo, rollback, admin/biblioteca/player/sala en ES/PL/EN, axe y 390/768/1440, reproducción real y chat intacto.

La suite normal incluye todos estos tests. `.github/workflows/i18n.yml` ejecuta controles, unit, contratos i18n, PostgreSQL y E2E con cuentas y vídeos sintéticos en infraestructura CI aislada. Un `<button>Guardar</button>`, `setSaved("Perfil guardado.")` o clave añadida solo a ES hace fallar CI. El workflow Docker sigue verificando la imagen completa en amd64/ARM64 sin desplegar en una instalación real.

## Añadir un cuarto idioma

Añadir el código a `SUPPORTED_LOCALES` y su catálogo completo `satisfies Catalog`; actualizar `catalogs`, `intlLocales` y `localeNames`. Revisar las formas plurales necesarias (ampliar el esquema a `zero`/`two` si el nuevo idioma las usa), fallback, defaults y prioridad prelogin. Actualizar pruebas parametrizadas, reglas, documentación y AGENTS para que todos los idiomas tengan la misma condición. No quitar ES/PL/EN.
